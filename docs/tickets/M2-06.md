# M2-06 · network egress allow-list and shared HttpClient

**Draft ID:** M2-06 · **Labels:** `type:feature` `area:desktop` `p0` · **Size:** M · **Blocked by:** M0-09 (merged) · **Packages:** apps/desktop, packages/mail · **SENSITIVE**

**Read first:** docs/brief.md §5.10 › No network except; docs/security/network.md (all of §1-2); docs/adr/0004-incremental-sync-and-imap.md (Consequences); `apps/desktop/src/main/security.ts`

**Context**
Today the filter has an empty allow-list. Provider adapters need one HTTP client with the exact hosts they may call, and the connected IMAP/SMTP hosts added at runtime.

**Scope**
- Worker-side `HttpClient` (injected into adapters) that checks every request against the allow-list; session-level filter in main keeps the same rules.
- Static hosts from docs/security/network.md rows H1-H5 (Google/Microsoft APIs and token endpoints); dynamic hosts: IMAP/SMTP host:port of each connected account, added on connect and removed on account removal.
- Blocked requests log host only; no wildcard patterns; the RFC 8058 unsubscribe path (X1) is NOT added here (M5).
- Update docs/security/network.md and threat-model.md in the same PR if any row changes.

**Acceptance criteria**
- [ ] A request to an unlisted host fails with a typed error and no network call is made (named test).
- [ ] Adding an account adds its IMAP host; removing it removes the host again (named test).
- [ ] No wildcard or suffix match: `evil-gmail.googleapis.com.example` is blocked.
- [ ] Timeouts and cancellation via `AbortSignal` are honoured.
- [ ] Existing `security.test.ts` baseline still passes.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Rate limiting (M2-07), provider calls, unsubscribe POST (M5).
