# M2-20 · Overview figures: emails archived, attachments saved (count + size)

**Draft ID:** M2-20 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M4-14 (merged first), docs PR "product-framing-20261119" · **Packages:** packages/core, packages/db, packages/testing, apps/desktop

**Why (decided 2026-11-19):** Pochimail helps you export/save attachments, unsubscribe from useless newsletters, archive mail you don't need, and keep only relevant mail. Archiving does not free mailbox space, so "GB you can free" is the wrong headline. The figures that matter:
- **emails archived** (count; and emails you could archive),
- **attachments saved** (count and total size in GB/MB),
- (existing) newsletters unsubscribed.
Total mailbox GB is not a goal. Found because the Message entity has no size (M4-14 review).

**Scope**
- Core: attachment metadata on the Message entity (count, per-attachment sizeBytes, mime type, filename hash only); an archived counter / archived-by-Pochi flag from the action log.
- DB: persist (idempotent migration; old rows default to unknown/0), aggregate per category and per account with GROUP BY (no per-message loops).
- Fixtures (dev/test only): attachment counts and sizes plus archived counts consistent with the mock dataset (update brief §6 numbers in the same PR).
- Overview + Summary: show "N emails archived", "N attachments saved · X GB", "N newsletters unsubscribed"; recommendations phrased the same way (e.g. "Save 412 attachments (1.2 GB)", "Archive 9,206 promotions"). Bytes formatted per locale (en/fr/ja).
- Provider tickets: one line each in M2-09 (Gmail parts/size), M2-10 (Graph attachments/size), M2-11 (IMAP BODYSTRUCTURE sizes) saying they must map attachment metadata.

**Acceptance**
- [ ] Full-scale fixture scan asserts attachment count/size and archived totals from the brief.
- [ ] Overview shows the three figures; a test guards the formatted values in en, fr, ja.
- [ ] Migration test: an old database opens and keeps its rows.
- [ ] No "GB you can free" copy left in code or catalog.
