# M1-02 · domain entities + zod schemas

**Draft ID:** M1-02 · **Labels:** `type:feature` `area:core` `p0` · **Size:** L · **Blocked by:** M1-01 · **Packages:** packages/core

**Read first:** docs/brief.md §3, §5.2, §5.6; docs/adr/0003-hexagonal-core-events-outbox.md

**Context**
The domain model is what ports, events, the pipeline and the UI all share. Schemas make it validated at every boundary (provider, DB, IPC).

**Scope**
- Entities with zod schemas and inferred types: Account (provider kind `gmail|graph|imap`, `workspaceId`), Message, Thread, SenderStats, Attachment, Category (the 7 fixed categories), Suspicious flag, Topic, Signal (6 kinds), Suggestion, Action, ActionLog.
- Pure constructors/guards where invariants exist (e.g. a Suggestion always carries reasons + confidence in 0..1).
- Schema versioning field on persisted entities.
- Serializable: every entity round-trips through JSON without loss.

**Acceptance criteria**
- [ ] Every entity round-trips `schema.parse(JSON.parse(JSON.stringify(x)))` (property-style test over generated samples).
- [ ] A Suggestion without reasons or with confidence outside 0..1 is rejected (named test).
- [ ] Category enum has exactly the 7 brief categories; an unknown category fails parsing.
- [ ] Account without a `workspaceId` or with an unknown provider kind is rejected.
- [ ] No dependency on any IO library; zod only.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Persistence mapping (M2), UI view models (M4).
