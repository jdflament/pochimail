# M1-04 · typed domain event catalog + in-process EventBus

**Draft ID:** M1-04 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M1-02 · **Packages:** packages/core

**Read first:** docs/brief.md §5.3 (live UI updates, events); docs/adr/0003-hexagonal-core-events-outbox.md

**Context**
The UI and pipeline stages communicate through events; a typed catalog keeps producers and consumers honest and feeds IPC in M4.

**Scope**
- Discriminated-union event catalog (sync progress, message classified, signal detected, suggestion proposed, action applied/undone, account state changed, …) with versioned payload schemas.
- In-process `EventBus` implementation: typed `publish`/`subscribe`, per-subscriber isolation, unsubscribe, ordering per publisher.
- Event batching helper for high-rate streams (coalesce within a window).

**Acceptance criteria**
- [ ] A throwing subscriber does not prevent other subscribers from receiving the event (named test).
- [ ] Events are delivered in publish order to each subscriber.
- [ ] Unsubscribed handlers receive nothing after unsubscribe.
- [ ] Publishing an event that fails its schema is rejected, not delivered.
- [ ] Batching helper emits one coalesced event per window for 1,000 rapid events.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Transport over IPC (M4-01), persistence of events (M1-07 outbox).
