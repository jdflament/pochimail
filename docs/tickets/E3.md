# Epic: M3 Local AI

**Draft ID:** E3

**Goal:** Classify and understand mail entirely on-device, accurately and fast, per hardware tier.

**Done when:** Models download per hardware tier; rules + decision heads + LLM classify the fixture with target precision; signals, topics, explanations; on-device learning; accuracy + latency gates in CI.

**Planned children**
- [ ] Model manifest + resumable SHA-256 downloader + hardware tier detection (T0/T1/T2)
- [ ] Rule engine (headers, domains, reply history)
- [ ] Sender + template aggregation/clustering
- [ ] Embeddings runtime in model-host utility process
- [ ] Decision heads + temperature calibration + training pipeline in packages/ai/training (synthetic multilingual corpus, P12)
- [ ] LLM host (node-llama-cpp) with JSON-schema constrained decoding + zod
- [ ] Signals (needs reply, waiting on them, important sender, has document, time-sensitive/deadlines, old & never opened) + Suspicious flag
- [ ] Topic discovery/naming (5–8) + user edits
- [ ] Explanations ("weekly promo, you never opened it")
- [ ] On-device learning (kNN + local refit)
- [ ] Content-hash cache + power awareness
- [ ] Eval gates in CI (accuracy + emails/min per tier)
- [ ] T0 fallback copy

**Read:** Brief §3, §5.8, §9; ADR 0006.

_Children become repo issues when the milestone starts. Source: docs/plan.md §2._
