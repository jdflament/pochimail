# M1-08 · staged pipeline runner

**Draft ID:** M1-08 · **Labels:** `type:feature` `area:core` `p0` · **Size:** L · **Blocked by:** M1-07 · **Packages:** packages/core

**Read first:** docs/brief.md §5.3 (pipeline, backpressure)

**Context**
Sync → classify → signals must stream with bounded memory and be pausable and resumable (battery, offline, user pause).

**Scope**
- Staged runner: batches flow through stages with bounded concurrency and backpressure.
- Pause/resume via AbortController; no work is lost or duplicated across pause.
- Resumable cursors persisted through the repository port after each committed batch.

**Acceptance criteria**
- [ ] A slow downstream stage throttles the upstream stage; in-flight items never exceed the configured bound (named test).
- [ ] Pausing mid-run and resuming processes every item exactly once.
- [ ] Restarting from a persisted cursor skips already-committed batches.
- [ ] A failing item is retried/dead-lettered via the queue without stalling the run.
- [ ] Deterministic tests with the fake clock; no sleeps.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Real schedulers/power awareness (M7, M3).
