# M2-17 · offline detection and queued actions

**Draft ID:** M2-17 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M1-14, M2-15 · **Packages:** packages/core, packages/testing

**Read first:** docs/brief.md §7b › Offline behavior; docs/adr/0004-incremental-sync-and-imap.md; docs/brief.md §5.3 › Idempotent actions; `packages/core/src/use-cases/apply-action.ts`

**Context**
Offline is a normal state: sync pauses by itself, approved actions wait and replay.

**Scope**
- Online/offline signal through the `Platform` port; `Offline` provider errors pause sync and set one status (no repeated events).
- Actions approved offline are persisted as jobs (status 'will apply when back online'), applied on reconnect in order, idempotent, undoable as usual.
- Overlap with E5 'offline action queue': this ticket owns the queue and replay; the E5 ticket only adds UI copy.

**Acceptance criteria**
- [ ] Going offline mid-sync pauses and resumes to the same final state (named test with fake offline).
- [ ] An action queued offline applies once after reconnect, even if reconnect flaps (named idempotency test).
- [ ] Undo of a replayed action works across a restart (via repository).
- [ ] Only one offline status event is emitted per transition.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: UI copy and Activity screen (M5).
