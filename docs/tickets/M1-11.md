# M1-11 · eval harness: precision/recall per category and signal

**Draft ID:** M1-11 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M1-10 · **Packages:** packages/testing (eval),.github/workflows

**Read first:** docs/brief.md §3 (eval set), §8 › CI gate

**Context**
Accuracy must be measurable from day one so M3 can gate on it. Replaces the M0-05 eval stub.

**Scope**
- Harness running a Classifier/signal detector over the fixture and comparing to ground truth.
- Precision/recall (and support) per category and per signal, JSON report.
- Committed baseline file and a CI job that fails on regression beyond a tolerance.
- Replace the stub `eval` job from M0-05.

**Acceptance criteria**
- [ ] Metrics are correct on a hand-computed tiny fixture (named test).
- [ ] A classifier degraded on purpose makes the CI comparison fail; the baseline run passes.
- [ ] Report JSON schema is validated and uploaded as a CI artifact.
- [ ] Harness takes any `Classifier` implementation (usable unchanged in M3).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Latency/throughput gates (M3).
