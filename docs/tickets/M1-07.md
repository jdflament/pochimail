# M1-07 · transactional outbox + persistent job queue semantics (in-memory impl + contract suite)

**Draft ID:** M1-07 · **Labels:** `type:feature` `area:core` `p0` · **Size:** L · **Blocked by:** M1-03, M1-04 · **Packages:** packages/core, packages/testing

**Read first:** docs/brief.md §5.3; docs/adr/0003-hexagonal-core-events-outbox.md

**Context**
Reliable background work needs at-least-once delivery with leases and retries. The contract suite defines the behaviour SQLite must match in M2.

**Scope**
- Outbox: events appended in the same transaction as state changes; relay publishes after commit, marks delivered.
- Job queue: enqueue, lease with expiry, ack, nack with retry (exponential backoff + jitter), dead-letter after max attempts.
- In-memory implementation driven by the `Clock` port (no real timers in tests).
- Exported contract test suite (`runJobQueueContract(factory)`, `runOutboxContract(factory)`).

**Acceptance criteria**
- [ ] A job whose lease expires is redelivered to another consumer (named test).
- [ ] A crashed relay re-publishes undelivered outbox events after restart; delivered ones are not duplicated.
- [ ] Retries follow backoff with jitter within documented bounds (fake clock); after max attempts the job is dead-lettered.
- [ ] State change and outbox append roll back together when the transaction fails.
- [ ] Contract suites are exported and run against the in-memory impl in CI.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: SQLite implementation (M2).
