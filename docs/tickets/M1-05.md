# M1-05 · policies: autonomy, invariants, authorize

**Draft ID:** M1-05 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M1-02 · **Packages:** packages/core

**Read first:** docs/brief.md §1 (principles), §2, §5.6

**Context**
Safety rules must live in one pure, exhaustively tested place so no code path can bypass them.

**Scope**
- Autonomy policy: Just look / Suggest / Autopilot and what each permits.
- Invariants: never delete mail, People category is protected from auto-actions, confidence threshold gates Autopilot.
- `authorize(action, context)` that always allows in v1 but is the single call-site every action passes through.
- Table-driven exhaustive tests across the policy × category × confidence matrix.

**Acceptance criteria**
- [ ] No action of kind `delete` can be authorized under any policy (named test).
- [ ] People-category items are never auto-actioned in Autopilot.
- [ ] Below-threshold confidence never auto-applies; at/above threshold applies only in Autopilot.
- [ ] Just look permits no mutation; Suggest permits none without explicit user confirmation.
- [ ] Exhaustiveness: adding a new action kind or policy fails typecheck until handled.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: UI for policy selection (M5).
