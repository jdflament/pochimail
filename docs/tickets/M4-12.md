# M4-12 · Connect screen (Google, Microsoft, Other email provider)

**Draft ID:** M4-12 · **Labels:** `type:feature` `area:desktop` `p0` · **Size:** M · **Blocked by:** M4-10, M4-11, M4-02 · **Packages:** apps/desktop

**Read first:** docs/brief.md §7 item 2, §7b › Account flow; docs/design/screens/html/Connect.html + the approved M4-11 drafts; docs/adr/0007-oauth-credentials-scopes.md

**Context**
Connect against the fixture-backed worker: buttons call `accounts.connect`; real OAuth/IMAP arrive with M2 through the same procedure.

**Scope**
- Google/Microsoft buttons, 'Other email provider' flow from the approved draft, 'My promises' list, 'you can add more accounts later'.
- Result handling: success → Setup, cancelled → sign-in-cancelled state, failure → error state; add-another-account entry from the switcher skips Setup.
- No password or token ever enters renderer state beyond the form field's lifetime; the app-password field is cleared after submit.

**Acceptance criteria**
- [ ] Success advances to Setup; a simulated cancel shows the cancelled state with one primary action (named tests).
- [ ] App-password field value is not kept after submit and never logged (named test).
- [ ] Add-another-account from the switcher skips Setup and starts that account's sync only.
- [ ] Keyboard and screen-reader labels on every control; light/dark verified in Storybook or the gallery.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Real OAuth (M2-05), presets data (M2-13).
