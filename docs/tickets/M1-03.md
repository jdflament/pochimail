# M1-03 · port interfaces + UnitOfWork

**Draft ID:** M1-03 · **Labels:** `type:feature` `area:core` `p0` · **Size:** L · **Blocked by:** M1-02 · **Packages:** packages/core

**Read first:** docs/brief.md §5.2, §5.9; docs/adr/0003-hexagonal-core-events-outbox.md; docs/adr/0004-incremental-sync-and-imap.md

**Context**
Ports are the seam that lets M2 (real providers/SQLite), M3 (real AI) and M4 (UI) proceed in parallel against in-memory stand-ins.

**Scope**
- `MailProvider` with declared capabilities (labels, folders, archive, batch, delta) so use cases branch on capability, not provider name.
- Repository ports (accounts, messages, threads, senders, suggestions, action log, topics, cursors).
- `BlobStore`, `SecretStore`, `Classifier`, `Embedder`, `LlmProvider`, `Exporter`, `JobQueue`, `EventBus`, `Scheduler`, `Notifier`, `PowerMonitor`, `Platform` (incl. `deviceName`).
- `UnitOfWork` port: repository writes + outbox append commit atomically.
- All port methods return `Result` (M1-01) and accept an `AbortSignal` where long-running.

**Acceptance criteria**
- [ ] Ports compile with no runtime code beyond types and capability constants.
- [ ] A type test shows a use case can be written against `MailProvider` capabilities without knowing the provider kind.
- [ ] `UnitOfWork` signature makes it impossible to append to the outbox outside a transaction (type test).
- [ ] `packages/core` still imports nothing from Node/Electron/DOM.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Any adapter implementation (M1-09, M2).
