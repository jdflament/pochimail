# M2-08 · recorded API fixtures: HTTP replay and scripted IMAP server

**Draft ID:** M2-08 · **Labels:** `type:feature` `area:infra` `p0` · **Size:** M · **Blocked by:** M1-09, M1-10 (merged), M2-06 · **Packages:** packages/testing

**Read first:** docs/brief.md §8 › Testing (adapters tested against recorded API fixtures); docs/adr/0004-incremental-sync-and-imap.md; `packages/testing/src/mail-provider-contract.ts`, `fixture-mailbox/`

**Context**
Provider adapters must be tested without real accounts. One shared harness avoids three ad-hoc ones.

**Scope**
- HTTP record/replay fixture format (scrubbed: no tokens, addresses or real message text; fixtures are synthetic or generated from the fixture mailbox) with a replay server usable by the Gmail and Graph adapters.
- Scripted IMAP server (or an in-process fake speaking the subset imapflow needs: LIST, SELECT, FETCH, STORE, MOVE, CONDSTORE/QRESYNC, IDLE) backed by the fixture mailbox.
- A small scrub check that fails if a fixture contains an email address outside the fixture domain or a token-looking string.

**Acceptance criteria**
- [ ] The harness serves a full fixture mailbox through each protocol and the same mailbox yields the same `IncomingMessage` set (named test).
- [ ] Scrub check fails on a planted token and on a real-looking address.
- [ ] Can simulate 429/`Retry-After`, expired cursor (404 / UIDVALIDITY change), dropped connection.
- [ ] Exported for `packages/mail` tests via a public entry point.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: The adapters themselves.
