# M2-18 · restart-resume integration on SQLite

**Draft ID:** M2-18 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M2-03, M1-14, M2-09 · **Packages:** packages/db, packages/testing

**Read first:** docs/brief.md §5.3 (jobs survive restarts), §8 › Testing; docs/plan.md §2 (M2 done-when)

**Context**
Proves the milestone's done-when with real storage: kill, reopen, same final state.

**Scope**
- Integration test: fixture provider + SQLite + scan pipeline; hard-stop the run at several points (mid-batch, between sync and classify, after outbox write), reopen the database, continue.
- Same scenario with a rate-limited and an offline interval.
- Runs in CI on the 3-OS matrix (no Electron needed: Node + the same driver).

**Acceptance criteria**
- [ ] Final database content equals an uninterrupted run, compared by a stable dump (named test).
- [ ] No event delivered twice, none lost (outbox).
- [ ] Rate-limit and offline intervals resume without manual action.
- [ ] Runs on macOS, Windows and Linux CI.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Real accounts (manual smoke).
