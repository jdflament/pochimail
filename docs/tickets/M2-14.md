# M2-14 · multi-account and All-accounts aggregation

**Draft ID:** M2-14 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M2-03, M2-09 · **Packages:** packages/core, packages/db

**Read first:** docs/brief.md §4 (multiple accounts), §7b › Account flow; docs/plan.md D4, D5; `packages/core/src/ports/repositories.ts`

**Context**
Several accounts of mixed providers in one workspace, with a unified view and per-account filtering.

**Scope**
- Provider factory registry: account kind (gmail/graph/imap) → `MailProvider` + token source; core never branches on kind.
- Aggregated queries across accounts (category counts, sender stats, digest, hidden-empty-category data for D5) plus per-account filter.
- Add-another-account starts a background sync for that account only; remove-account deletes its data and revokes (calls M2-05).

**Acceptance criteria**
- [ ] Counts for All accounts equal the sum of per-account counts (named test, two accounts, two provider kinds).
- [ ] Syncing one account never writes another's rows (named workspace/account isolation test).
- [ ] Removing an account leaves the other account's data and cursors intact.
- [ ] Empty categories are reported as empty so the UI can hide them (D5).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Account switcher UI (M4-09).
