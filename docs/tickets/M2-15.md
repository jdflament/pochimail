# M2-15 · adaptive polling scheduler

**Draft ID:** M2-15 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M1-14 · **Packages:** packages/core, apps/desktop

**Read first:** docs/adr/0004-incremental-sync-and-imap.md (Adaptive polling); docs/brief.md §5.5, §5.9; `packages/core/src/ports/scheduler.ts`, `power-monitor.ts`

**Context**
Fresh mail without wasting battery or quota.

**Scope**
- Cadence: ~1 min window focused, ~5 min visible but idle, Keep-it-tidy cadence when hidden; paused on sleep, offline, battery saver.
- New small port for window activity (focused/visible/hidden) fed by main; deterministic with fake clock and fake power monitor.
- One poll per account at a time; a running sync is never doubled.

**Acceptance criteria**
- [ ] Cadence switches with activity state (named test per state, fake clock).
- [ ] Sleep/offline/battery saver pause polling and resume once on return (named tests).
- [ ] Overlapping triggers produce one sync run (named test).
- [ ] Contract suites for the new port are exported.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: IDLE wake-ups (M2-16), cadence settings UI (M7).
