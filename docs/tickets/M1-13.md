# M1-13 · use cases: DetectSignals, ProposeSuggestions, BuildDigest + summary model

**Draft ID:** M1-13 · **Labels:** `type:feature` `area:core` `p0` · **Size:** L · **Blocked by:** M1-12 · **Packages:** packages/core

**Read first:** docs/brief.md §3 (signals), §7 (summary)

**Context**
Turns classified mail into the things the user actually sees: signals, sender-level suggestions with reasons, and a ‘what's new’ summary.

**Scope**
- `DetectSignals` for the 6 signals (needs reply, waiting on them, important sender, has document, time-sensitive, old & never opened).
- `ProposeSuggestions` at sender level with reasons and confidence, respecting policies (M1-05).
- `BuildDigest` + summary report model (‘what's new’ only; no totals of old mail).

**Acceptance criteria**
- [ ] Each signal fires on its positive fixture and not on its negative (one named test per signal).
- [ ] A suggestion never proposes an action forbidden by policy (People, delete).
- [ ] Every suggestion carries at least one human-readable reason and a confidence.
- [ ] Digest after a second sync contains only items new since the first.
- [ ] Deterministic output for a given fixture seed.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Learning from user feedback (M3), UI rendering (M4).
