# M4-16 · the 8 required states as components and fixtures

**Draft ID:** M4-16 · **Labels:** `type:feature` `area:ui` `p0` · **Size:** M · **Blocked by:** M4-04, M4-08 · **Packages:** packages/ui, apps/desktop

**Read first:** docs/brief.md §6 › Required states, States and motion; docs/design.md › Required states; docs/design/screens/html/States.html, light/06-states.png

**Context**
Each state has the mascot pose, exact copy and one primary action, and can be triggered by a fixture event.

**Scope**
- States: sign-in cancelled, offline (status line, never a pop-up), account needs reconnecting, model download failed (rules fallback), provider rate limit (auto-resume with time), empty category, update ready (restart now / what's new). See open question about 'nothing to do'.
- Triggers from worker events/fixtures (`RateLimited`, `Offline`, `needs_reauth`…) so M2/M3/M8 later only emit the real events.

**Acceptance criteria**
- [ ] Each state renders the specified pose, copy and exactly one primary action (one named test each).
- [ ] Offline state is a status line, never a modal (named test).
- [ ] Rate-limit state shows a resume estimate and clears itself when the event stream resumes.
- [ ] Light and dark stories exist for all of them (consumed by M4-18/19).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Real update flow (M8), real model download (M3).

**Decision (JD 2026-11-18):** build 8 states: the 7 from design (incl. "Update ready") plus "Nothing to do" from brief §6. "Nothing to do" has no mockup: derive copy and mascot pose from the "Empty category" state and show it in the gallery for JD review.
