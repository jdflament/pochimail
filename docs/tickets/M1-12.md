# M1-12 · use cases: ConnectAccount, RunIncrementalSync, ClassifyBatch

**Draft ID:** M1-12 · **Labels:** `type:feature` `area:core` `p0` · **Size:** L · **Blocked by:** M1-06, M1-08, M1-09 · **Packages:** packages/core

**Read first:** docs/brief.md §8 › Backend use cases, §5.3; docs/adr/0004-incremental-sync-and-imap.md

**Context**
First real orchestration: account connected, mail synced by cursor, messages classified in batches, all through ports.

**Scope**
- `ConnectAccount` (stores account + secret via ports, emits events).
- `RunIncrementalSync` using provider delta/cursor, resumable, emitting progress events.
- `ClassifyBatch` with a stub classifier reading fixture ground-truth labels (real classifier in M3).

**Acceptance criteria**
- [ ] Second sync after new mail fetches only the delta (named test).
- [ ] Sync interrupted and resumed yields the same final state as an uninterrupted run.
- [ ] A `RateLimited` provider error pauses sync into the right account state and retries later.
- [ ] Connecting the same account twice is idempotent.
- [ ] Runs entirely against in-memory adapters from M1-09.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Real providers (M2) and real classifier (M3).
