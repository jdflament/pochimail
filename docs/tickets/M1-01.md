# M1-01 · core primitives: branded IDs, Result type, typed errors, Clock + Logger ports with redaction

**Draft ID:** M1-01 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M0-04 · **Packages:** packages/core

**Read first:** docs/brief.md §8 › Backend; docs/adr/0003-hexagonal-core-events-outbox.md

**Context**
Every other core piece builds on a small, dependency-free vocabulary. Getting IDs, errors and logging right first prevents ID mix-ups and PII leaking into logs later.

**Scope**
- Branded ID types (`AccountId`, `MessageId`, `ThreadId`, `ActionId`, …) with constructors that validate; no plain `string` crossing a port.
- `Result<T, E>` type with `ok`/`err` helpers and exhaustive narrowing; no thrown exceptions for expected failures.
- Typed error hierarchy (`DomainError`, `ProviderError` incl. `RateLimited`, `Offline`, `AuthExpired`, `Conflict`) with stable `code` fields.
- `Clock` port (`now`), plus a fake clock in `packages/testing` stub location if M1-09 is not merged yet.
- `Logger` port with a redaction layer: addresses, subjects, bodies and tokens are replaced before any sink sees them.

**Acceptance criteria**
- [ ] Passing a `MessageId` where an `AccountId` is expected fails typecheck (type test).
- [ ] A log call containing an email address, subject, body text or bearer token reaches the sink redacted (test names the leak it prevents).
- [ ] Redaction is applied by default; a logger created without options cannot emit raw fields.
- [ ] `packages/core` imports no `node:*`, `electron` or DOM types (lint passes).
- [ ] Unit tests run through the package's public exports only.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Concrete log sinks (file/console) — adapters live elsewhere.
