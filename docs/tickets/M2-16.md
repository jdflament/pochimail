# M2-16 · IMAP IDLE wake-ups

**Draft ID:** M2-16 · **Labels:** `type:feature` `area:mail` `p0` · **Size:** M · **Blocked by:** M2-11, M2-15 · **Packages:** packages/mail

**Read first:** docs/adr/0004-incremental-sync-and-imap.md (IDLE, Wake-up column); docs/security/oauth-verification.md (checklist G6); docs/brief.md §5.3

**Context**
IMAP accounts get push-like wake-ups; Gmail/Graph IDLE stay opt-in and may be dropped.

**Scope**
- IDLE on INBOX for IMAP accounts by default; re-issue every ~25 min; reconnect with backoff + jitter; paused on sleep/offline.
- IDLE only signals 'changed'; the scheduler then runs a delta sync.
- A per-account `realtimeUpdates` flag exists for Gmail/Graph (default off); no broader scope is requested in this ticket.

**Acceptance criteria**
- [ ] A server EXISTS push triggers exactly one delta sync (named test against the scripted server).
- [ ] Connection drop reconnects with bounded backoff and does not busy-loop (named test).
- [ ] Gmail and Graph accounts never open IDLE unless the flag is on (named test).
- [ ] Sleep/offline pause and resume it.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Settings UI and the broader-scope re-prompt (M7); dropping Gmail IDLE if Google refuses (decision after G6).
