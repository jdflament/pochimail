# M4-01 · IPC contract and streaming subscriptions

**Draft ID:** M4-01 · **Labels:** `type:feature` `area:desktop` `p0` · **Size:** L · **Blocked by:** M0-09, M0-14 (merged) · **Packages:** apps/desktop · **SENSITIVE**

**Read first:** docs/adr/0002-electron-process-model-and-ipc.md (all, incl. IPC transport research); docs/brief.md §5.3 › Live UI updates, §5.10 › Electron hardening; `apps/desktop/src/shared/ipc/echo.ts`, `batching.bench.test.ts`, `src/preload/preload.ts`, `src/main/worker-link.ts`

**Context**
The typed bridge every screen uses: procedures with zod input/output and event subscriptions over the renderer↔worker MessagePort.

**Scope**
- Production RPC + subscription layer in `src/shared/ipc/` replacing the echo: shared zod schemas, queries/mutations, subscriptions streaming domain events and progress.
- Event batching per ADR 0002: flush every 50 ms or max batch size, ack-gated window of 2, per-key coalescing of progress, teardown on port close; validated once per batch.
- Preload exposes only the port request plus the few OS calls (open mail-app link, show in Finder, choose folder); nothing mail-related.
- First contract surface (names only, handlers in M4-02): `accounts`, `scan`, `overview`, `digest`, `settings`, `app.state`.

**Acceptance criteria**
- [ ] Events arrive in order, none dropped, under a slow consumer (promote the M0-14 benchmark's lossless check to a real test).
- [ ] Invalid input or output is rejected on both sides with a typed error (named test).
- [ ] Closing the port tears down subscriptions (no leak test).
- [ ] Preload surface snapshot test: only the allowed methods exist; no `ipcRenderer`, no Node.
- [ ] Traffic renderer↔worker does not pass through a main-process handler (test kept from M0-09).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Handlers backed by real use cases (M4-02), screens.
