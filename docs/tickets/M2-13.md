# M2-13 · provider presets from a bundled ISPDB snapshot

**Draft ID:** M2-13 · **Labels:** `type:feature` `area:mail` `p0` · **Size:** M · **Blocked by:** M2-11 · **Packages:** packages/mail, docs

**Read first:** docs/adr/0004-incremental-sync-and-imap.md (Provider presets); docs/adr/0007-oauth-credentials-scopes.md (Yahoo, iCloud rows); docs/security/oauth-verification.md (checklist I1)

**Context**
Pick Yahoo/iCloud/Fastmail/GMX and get host, port and auth method with no network lookup.

**Scope**
- Bundled snapshot containing only supported presets, original headers kept, third-party notice added; no runtime ISPDB or MX lookup.
- `resolvePreset(address)` → host/port/security/auth (iCloud `imap.mail.me.com:993` app password; Yahoo app password first); unknown domain → manual entry defaults.
- Confirm the data-file licence (checklist I1) and record the answer in the PR; if unclear, stop and ask JD.

**Acceptance criteria**
- [ ] Each shipped preset resolves from a typical address and from an alias domain (named test per preset).
- [ ] Unknown domain makes no network call (named test with the egress filter).
- [ ] Notice file present and listed in the packaging config.
- [ ] Preset auth method matches ADR 0007 (no OAuth for Yahoo/iCloud).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: The provider-picker UI (M4-11/12), Yahoo OAuth (E8).
