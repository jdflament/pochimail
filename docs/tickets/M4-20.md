# M4-20 · storage-protection prompt on Linux (basic_text) and passphrase option

**Draft ID:** M4-20 · **Labels:** `type:feature` `area:desktop` `p0` · **Size:** S · **Blocked by:** M2-04, M4-01, M4-11 · **Packages:** apps/desktop · **SENSITIVE**

**Read first:** docs/adr/0005-local-storage.md (Key management, Linux basic_text); docs/security/threat-model.md; approved M4-11 draft; `apps/desktop/src/main/storage-key.ts`

**Context**
ADR 0005 left this UI to onboarding: when only `basic_text` is available the key must not be written silently.

**Scope**
- IPC procedure exposing `keyProtection`; before first key creation on `basic-text`, show the prompt: passphrase first (derive the key, never stored), 'store without protection' only as a second explicit choice.
- Choice persisted as a flag only (never the passphrase); unlock prompt at launch when a passphrase is set.

**Acceptance criteria**
- [ ] On `basic-text` no key file is written before the user chooses (named test with a faked backend).
- [ ] Passphrase path: wrong passphrase cannot open the database; right one can after restart (named test).
- [ ] The passphrase never reaches logs, disk or renderer state beyond the input's lifetime.
- [ ] On `os-keychain` the prompt never appears.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: A real libsecret CI job (nice-to-have noted in ADR 0005).
