**Scope**

- Catch what matters (people waiting, deadlines, important people; 'I never clean these'; Review; secondary to the four core jobs, JD 2026-11-19) and Clean up (figures: emails archived and emails that could be archived, attachments saved with count and size, newsletters unsubscribed; storage bar **OPEN for JD** — what it shows, or drop it; action-phrased recommendations ordered by impact, closing never-cleaned line) from queries kept fresh by events.

**Acceptance criteria**
- [ ] Events change the figures with at most one refetch per second; the old figures stay on screen (no flicker) (named test with a scripted event stream). `ScanProgressed` carries only processed/total, so waiting/deadlines/cleanable cannot be patched from events.
- [ ] Pause stops progress and Resume continues from the same point (named test over the real IPC layer).
- [ ] Fixture numbers equal the brief's mock dataset (named golden test). **Partly unmet in M4-14:** email and category totals are asserted; the 7 waiting / 3 deadlines / 12 important figures are an accepted gap until the M3 detectors (JD 2026-11-19); the emails-archived and attachment count/size figures wait for M2-20 (entity `sizeBytes`, persistence, fixtures). Clean up shows email counts until then. Archiving does not free mailbox space: no 'GB you can free'/freeable figure.
- [ ] Empty accounts show the 'nothing to do' or empty state, not zeros in a ledger.
- [ ] Usable at 960, 860 and phone width (checked in M4-19 visual tests).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.
