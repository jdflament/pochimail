# M2-04 · SecretStore via Electron safeStorage and the database key

**Draft ID:** M2-04 · **Labels:** `type:feature` `area:desktop` `p0` · **Size:** M · **Blocked by:** M0-09, M0-12 (merged) · **Packages:** apps/desktop, packages/db · **SENSITIVE**

**Read first:** docs/brief.md §5.10 › Data at rest, Least-privilege; docs/adr/0005-local-storage.md (key management, Linux `basic_text`), docs/adr/0002-electron-process-model-and-ipc.md; `apps/desktop/src/main/storage-key.ts`, `worker-link.ts`; docs/security/threat-model.md

**Context**
`safeStorage` only works in the main process, but tokens and the DB key are needed in the worker. Main owns the keychain; the worker reaches it through a narrow main↔worker channel (not the renderer).

**Scope**
- `SecretStore` adapter for the worker backed by a main-process service using async `safeStorage` calls; encrypted values stored in a file in the app data dir; values never logged.
- Database key: `loadOrCreateDatabaseKey` result handed to the worker at start (consumed by M2-01).
- Respect `keyProtection` (`os-keychain` / `basic-text` / `unavailable`): no silent write on `basic-text`; expose the state so onboarding (M4-20) can ask. Default behaviour without a choice: refuse to store, typed error.

**Acceptance criteria**
- [ ] The adapter passes the exported `secret-store-contract` from `packages/testing` unchanged.
- [ ] Renderer cannot read or write secrets: the preload exposes no secret API and a test proves the port given to the renderer has no secret procedure (named test).
- [ ] On `basic-text`, setting a secret without an explicit user choice fails and writes nothing (named test).
- [ ] Worker restart still reads previously stored secrets; a corrupted entry returns a typed error, not a crash.
- [ ] Secret values never appear in logs (redaction test).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Passphrase/onboarding UI (M4-20), OAuth flow (M2-05).
