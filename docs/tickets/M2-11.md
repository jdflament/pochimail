# M2-11 · IMAP provider: read and incremental sync (imapflow)

**Draft ID:** M2-11 · **Labels:** `type:feature` `area:mail` `p0` · **Size:** L · **Blocked by:** M2-07, M2-08 · **Packages:** packages/mail · **SENSITIVE**

**Read first:** docs/adr/0004-incremental-sync-and-imap.md (IMAP row, first sync, resumability); docs/adr/0007-oauth-credentials-scopes.md (app password); docs/brief.md §4, §5.3; docs/adr/0009-store-metadata-not-mail.md

**Context**
Generic IMAP, the path for Yahoo, iCloud, Fastmail, GMX and unknown hosts. Read side only; actions come in M2-12.

**Scope**
- `imapflow` + `mailparser` (verify versions at scaffold, pin exact); TLS only, auth by app password (from `SecretStore`) or an XOAUTH2 token source.
- Cursor `UIDVALIDITY` + `HIGHESTMODSEQ`; CONDSTORE/QRESYNC when available, UID-range fallback otherwise; UIDVALIDITY change → full re-walk, `restarted: true`.
- Header-first FETCH (ENVELOPE, selected headers, FLAGS, SIZE), capped snippet only when cheap; no BODY[] persisted; `List-Unsubscribe` headers kept.
- Newest → oldest first sync, page tokens in the cursor so a restart resumes mid-walk.
- Capabilities derived from the server (`CAPABILITY`, `PERMANENTFLAGS`).

**Acceptance criteria**
- [ ] Passes `mail-provider-contract` and `sync-contract` unchanged against the scripted IMAP server.
- [ ] UIDVALIDITY change triggers a full re-walk with identical final state (named test); server without CONDSTORE uses the UID fallback (named test).
- [ ] Interrupted mid-walk and resumed → same state as uninterrupted (named test).
- [ ] Wrong password → `AuthExpired`; connection drop → retryable error, not a crash.
- [ ] No BODY[] fetch during sync (named D11 test).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Archive/keywords/folders (M2-12), IDLE (M2-16), presets (M2-13).
