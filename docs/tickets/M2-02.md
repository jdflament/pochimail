# M2-02 · core follow-ups: sync writes threads, persist signals, digest from stored state

**Draft ID:** M2-02 · **Labels:** `type:feature` `area:core` `p0` · **Size:** M · **Blocked by:** M1-12, M1-13 (merged) · **Packages:** packages/core, packages/testing

**Read first:** docs/brief.md §3 (signals), §7 item 5 (Summary: only what is new); docs/adr/0009-store-metadata-not-mail.md; `packages/core/src/use-cases/run-incremental-sync.ts`, `detect-signals.ts`, `build-digest.ts`; `packages/core/src/ports/repositories.ts`

**Context**
Three gaps left by M1: `RunIncrementalSync` never calls `ThreadWriter`, `DetectSignals` only emits `SignalDetected` (nothing stored), and `BuildDigest` takes `since` from its caller. A real database makes each of them a bug, so close them in core with the in-memory adapters first.

**Scope**
- `RunIncrementalSync` upserts a `Thread` for every stored message in the same transaction as the batch (idempotent on replay).
- New port `SignalRepository` (reader/writer, one row per message + signal kind) in `ports/repositories.ts` + in-memory adapter + exported contract suite in `packages/testing`; `DetectSignals` writes through it and still emits `SignalDetected`.
- New port `DigestStateRepository` (last digest timestamp per account); `BuildDigest` reads `since` from it and advances it after a successful digest; an explicit `since` stays optional for tests.
- Update `UnitOfWork` reads/writes bundles accordingly. D11: no bodies or attachments persisted (saved-document exception only); logs never contain subjects, addresses, snippets or tokens.

**Acceptance criteria**
- [ ] After a sync, every message's thread exists and thread counts match the messages (named test); replaying a batch creates no duplicate.
- [ ] Signals survive a fresh `DetectSignals` read from the repository without re-detecting (named test); re-running detection yields identical rows.
- [ ] Two consecutive digests with a sync in between: the second contains only mail new since the first, with no caller-supplied `since` (named test).
- [ ] New contract suites (`signal-repository`, `digest-state`) are exported and the in-memory adapters pass them.
- [ ] No existing M1 test changes meaning (CLI golden output unchanged).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: SQLite implementations (M2-03), pipeline wiring (M1-14).
