# M4-07 · i18n-ready string catalog and deviceName

**Draft ID:** M4-07 · **Labels:** `type:feature` `area:ui` `p0` · **Size:** S · **Blocked by:** M0-09 (merged) · **Packages:** apps/desktop, packages/ui

**Read first:** docs/plan.md P13; docs/brief.md §6 › Voice, §7 item 1; docs/design.md › Writing; `Platform` port (`deviceName`)

**Context**
English only in v1, but every string lives in a catalog so FR/JA arrive without code changes ('Your email never leaves this Mac' becomes the device name).

**Scope**
- Typed message catalog + tiny `t` with ICU-style plurals/numbers (pick the smallest dependency or write ~100 lines; justify in the PR); shared by renderer and ui stories.
- `deviceName` from the `Platform` port exposed through the IPC contract (Mac/PC/computer fallback).
- Lint/test rule: no user-facing string literals in screen components.

**Acceptance criteria**
- [ ] A test fails when a screen component contains a hard-coded user-facing literal.
- [ ] Plural and number formatting correct for 0/1/many in EN; a pseudo-locale (long, accented) renders without overflow in stories.
- [ ] Copy follows the voice rules: 'email/emails', never 'mails' (grep test over the catalog).
- [ ] `deviceName` falls back gracefully when the OS gives nothing.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: FR/JA translations (v1.x).
