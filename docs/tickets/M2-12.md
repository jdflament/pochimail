# M2-12 · IMAP actions: archive, keywords or folders, inverses

**Draft ID:** M2-12 · **Labels:** `type:feature` `area:mail` `p0` · **Size:** M · **Blocked by:** M2-11 · **Packages:** packages/mail · **SENSITIVE**

**Read first:** docs/adr/0004-incremental-sync-and-imap.md (IMAP archive/organize, Consequences); docs/brief.md §3, §5.3 › Idempotent actions; `packages/core/src/ports/mail-provider.ts`

**Context**
IMAP has no labels: archive and organize must be correct and reversible per server.

**Scope**
- Archive = MOVE (or COPY+STORE+EXPUNGE fallback) to the `\Archive` special-use folder; create `Archive` if absent.
- Organize as IMAP keywords when `PERMANENTFLAGS` allows `\*`, else folders under `Pochimail/` (opt-in); the capability tells the UI which applies.
- Every command returns its inverse; never deletes (no EXPUNGE of user mail outside a move).

**Acceptance criteria**
- [ ] Passes the command-related cases of `mail-provider-contract` against the scripted server.
- [ ] Archive then inverse restores the original folder and flags (named test).
- [ ] Server without `\*` PERMANENTFLAGS uses folders only after opt-in, otherwise refuses with a typed error (named test).
- [ ] No command path can delete a message (named test over the command set).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: UI wording about keywords vs folders (M5).
