# M2-05 · OAuth PKCE loopback in the system browser

**Draft ID:** M2-05 · **Labels:** `type:feature` `area:mail` `p0` · **Size:** M · **Blocked by:** M2-04 · **Packages:** packages/mail, apps/desktop · **SENSITIVE**

**Read first:** docs/adr/0007-oauth-credentials-scopes.md; docs/security/oauth-verification.md (§3-4); docs/brief.md §4, §5.10, §7b › Account flow; docs/security/network.md (H2-H5)

**Context**
Sign in once per provider, tokens kept in the keychain, never seen by the renderer.

**Scope**
- PKCE authorization-code flow for Google and Microsoft: random `state`, verifier, loopback `http://127.0.0.1:<random port>` listener that closes after one request; consent opens in the system browser (main opens it, the worker listens).
- Client IDs from build-time config / env (`POCHIMAIL_GOOGLE_CLIENT_ID`…), never hard-coded; missing config → clear typed error.
- Scope tiers per ADR 0007: read-only for Just look, modify (`gmail.modify`, `Mail.ReadWrite`) for Suggest/Autopilot; re-prompt when autonomy goes up. Send scopes stay out (M5, P2).
- Refresh tokens → `SecretStore`; access tokens in memory only; token refresh with `AuthExpired` when refresh fails (account → `needs_reauth`); revoke on removal.
- Cancel/timeout → `SignInCancelled` result (UI state in M4).

**Acceptance criteria**
- [ ] Wrong `state` or a second request to the loopback port is rejected and the listener closes (named tests).
- [ ] Cancel and 5-minute timeout return the cancelled result and free the port.
- [ ] Refresh failure sets the account to `needs_reauth` through core, nothing else stops (named test).
- [ ] Tokens never reach logs, the renderer or disk outside `SecretStore` (redaction + grep-style test).
- [ ] Runs against a local fake authorization server in tests; no real Google/Microsoft call in CI.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Yahoo OAuth (only if approved, E8), IMAP XOAUTH2 plumbing beyond the token source, verification filings (M2-19).
