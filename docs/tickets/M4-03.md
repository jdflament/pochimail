**Context**
The data-display pieces of the Overview, built from the design HTML to the token system.

**Scope**
- Ledger row (label, dotted leader, count, size, optional proportional bar that hides below 760px via container query), Signal row (large serif figure + text + Review), Recommendation row (sentence, reason, size, Review), Storage bar (solid/hatched, legend), Status strip (2px progress line + status line + Pause/Resume + View summary).
- shadcn conventions: CVA, `data-slot`, `asChild`, composition over boolean props; tokens only; tabular numbers.
- One Storybook story per component and variant, light and dark; props take plain data (no worker types).

**Acceptance criteria**
- [ ] Each component has stories in light and dark and passes the Storybook a11y check.
- [ ] Contrast test (M0-08) covers every new token pair used; no hard-coded colors (CI grep).
- [ ] Keyboard: every actionable element reachable with visible focus, 32px minimum target.
- [ ] Behaviour tests for interactions (Review click, Pause/Resume toggle, bar legend text) through the public export.
- [ ] Renders with long FR/JA labels without overflow (story proves it).
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Counting/rolling motion (M4-17), screens.
