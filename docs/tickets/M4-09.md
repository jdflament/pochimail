# M4-09 · responsive layout: sidebar, icon rail, bottom tabs, account switcher, hidden empty categories

**Draft ID:** M4-09 · **Labels:** `type:feature` `area:ui` `p0` · **Size:** M · **Blocked by:** M4-08, M4-03 · **Packages:** apps/desktop, packages/ui

**Read first:** docs/brief.md §6 › Responsive layout, §7 item 4 (Sidebar), §7b; docs/plan.md D5; docs/design/screens/narrow-window/04-overview-860.png, phone/04-overview.png, light/04-overview.png

**Context**
The frame every post-onboarding screen lives in.

**Scope**
- Container-aware layout (no separate mobile markup): ≥960 full sidebar; 760–960 icon rail; <760 edge-to-edge, ledger drops the bar; <560 top bar + bottom tabs (reachable in tests and Storybook; the desktop window minimum is 720).
- Sidebar: account switcher (All / per account / add another), Overview, 7 categories with counts (empty ones hidden, D5), Topics, Tools, disabled 'Teams · Soon'.
- Switcher filters every screen via the query layer; counts come from the aggregated queries.

**Acceptance criteria**
- [ ] Resizing across 960/760/560 swaps full sidebar → rail → bottom tabs with no remount of the content (visual + behaviour test).
- [ ] A category with zero emails for the current account selection is absent from the sidebar and appears when it gets mail (named test, D5).
- [ ] Switching account changes the counts everywhere without a page reload.
- [ ] Keyboard order and focus visible through sidebar, rail and tabs; `aria-current` on the active item.
- [ ] Test bar: behaviour tests through public entry points only (no tests of private helpers); each test guards a named failure (its name states the bug it prevents); contract suites are exported so M2 adapters (SQLite, real providers) reuse them unchanged.

**Out of scope**: Settings/Documents/Activity screens (E5-E7).
